# AED-001 completion evidence

## Persistence and migrations

`npm run db:migrate` applies the ordered SQL files in `database/migrations` and records each filename in `schema_migrations`. The server uses `DATABASE_URL` for Supabase/Postgres and a file-backed PGlite database for restart-safe local demo operation.

## Automated verification

- `npm run test:integration` covers valid AI-project and tool-access creation, list/get retrieval, server-side validation rejection, not-found handling, the separate requester audit event, and close/reopen persistence.
- `npm run typecheck` validates the web, shared contracts, and server.
- `npm run build` produces the browser bundle.
- A bundle scan for `SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_API_KEY`, `FISH_AUDIO_API_KEY`, n8n server variables, and GitHub token patterns returns no matches.

## UI evidence

`aed-001-persisted-queue.png` is captured from a running server and Vite client after the server-only demo reset seeded the three synthetic scenarios. The queue and selected detail are fetched from the API rather than imported seed state.

## Boundaries

Gemini analysis, human decisions, n8n execution, audio generation, and production authentication remain outside AED-001.
