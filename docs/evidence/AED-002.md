# AED-002 completion evidence

## Provider and provenance

The replaceable `GeminiAnalysisProvider` calls Gemini only from the trusted server, requests JSON structured output, validates the parsed result with the shared Zod contract, then applies semantic provenance checks. Each success or failure records provider, model, schema version, prompt version, latency, outcome, and a sanitized error code without saving credentials or raw secret-bearing transport payloads.

No paid or live Gemini call was made for completion. Integration tests inject a provider stub; the live adapter activates only when `GEMINI_API_KEY` is configured.

## Verification scenarios

- Successful maintenance analysis: model facts, assumptions, unknowns, questions, summary, and advisory recommendation persist in an immutable run.
- Malformed response: the Gemini adapter rejects a JSON object that fails the shared contract.
- Deterministic override: a model suggestion of `ready_for_discovery` is overridden to `needs_clarification`; a separate privacy scenario is overridden to `decline` and remains outside approval-ready status.
- Clarification loop: a requester answer persists separately with its own audit event; re-analysis creates a second run while retaining the first.
- Failure matrix: timeout, rate limit, invalid output, and unavailable key persist accurate retryable outcomes.

`npm run test:integration` and `npm test -- packages/domain/test/routing.test.ts` exercise these paths without a live provider. `aed-002-analysis-provenance.png` shows the saved model output and deterministic route as separate UI surfaces.
