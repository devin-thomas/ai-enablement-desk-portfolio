# AED-003 completion evidence

## Human ownership

Consequential decisions require a named reviewer, rationale, latest successful analysis ID, and expected request version. The server maps actions through the shared domain state machine, rechecks approval eligibility, performs a compare-and-swap version update, and writes the separate decision and human audit event in one transaction.

No model or browser path can directly write a human-owned final status. Automated model and deterministic system events remain separate from requester and human events.

## Verification scenarios

- Full lifecycle: submitted → analyzed → clarified → re-analyzed → reviewed → approved for discovery.
- Legal actions: approve for discovery, defer, decline, and request clarification.
- Governance blocks: high-risk privacy and incomplete requests fail direct approval API calls.
- Illegal transition: a second decision after approval returns a domain error without another decision or audit write.
- Concurrency: two simultaneous decisions with the same expected version yield one success and one conflict.
- Required evidence: missing reviewer identity or rationale is rejected at the server contract.
- Refresh safety: decision records and actor-separated audit events are read back from Postgres endpoints.

`npm run test:integration` covers these paths. `aed-003-human-decision-audit.png` shows a persisted named approval, its analysis binding, request version, and actor-separated timeline.
